# Apex 灵敏度实验台

一个**单文件网页应用**：在浏览器里用打靶任务，用配对比较的方式测出**你自己的腰射灵敏度**，并给出一个带统计依据的推荐值与不可分辨区间。

## 在线使用

**https://r1kka-ovo.github.io/apex-sens-lab/**

推荐直接打开这个网址（Chrome / Edge）。页面已经托管好，**不需要下载任何文件**，也仍然不联网、不上传任何数据 —— 跑的是同一个 `index.html`，所有计算和测试记录都在你自己浏览器里。

想离线用（比如断网、或想固定用某个版本），就把 `index.html` 存到本地双击打开，效果完全一样。

- 在线地址：<https://r1kka-ovo.github.io/apex-sens-lab/>
- 本地入口：`index.html`（单文件，约 3900 行，HTML + CSS + 原生 JS + Canvas 2D，**零依赖、零构建、不联网**）
- 核心约定：鼠标计数与视角 **1 计数 = 0.022°**（`DEG_PER_COUNT`），全程按这个比例换算

> 它不是「打靶小游戏打分」，而是一套**对照实验**：每个候选灵敏度都要在**难度构成一致、轨迹不同**的脚本下打若干段，用配对统计判断差异是否超过噪声。

## 快速开始

打开页面后是**模式选择页**，两条路：

| 选择 | 什么时候用 | 会发生什么 |
|---|---|---|
| **第一次测试** | 还没有任何记录 | 完整跑一遍：热身 → 状态校准 → 搜索 → 决胜 → 自动深化，约 15 分钟（标准档） |
| **导入测试数据** | 之前导出过 `.json` 记录 | 读入记录 → 显示已有结论 → 在**更窄的范围**里补测（默认 ±10%），把推荐值收得更细 |

开始前请确认：

1. 用 Chrome / Edge 打开并允许全屏
2. Windows「提高指针精确度」**已关闭**（设置 → 鼠标 → 其他鼠标选项 → 指针选项）
3. 游戏内 FOV / 显示比例与本页设置**一致**
4. 用你**平时最舒服的姿势**，不要为了多拿几分临时改姿势（否则测出来的是「不自然的你」的灵敏度）

操作：**空格**推进回合 · **Esc** 暂停 · **R** 重开本段（不计分，换新脚本）。测试期间右键 / 中键 / 侧键被屏蔽；若指针锁定丢失会自动暂停。

## 测试流程（第一次测试）

```
玩法说明
  ├─ 自适应热身（练到分数收敛，最多 3 次，不计分）
  ├─ 状态校准锚点（固定脚本 · 约 10 秒）
  ├─ 搜索阶段（标准档 6 轮，每轮 2 段）
  │    └─ 每轮：候选 vs 基准 → 胜者成为新基准，步长按结果收缩
  ├─ 模型推算实测对局
  ├─ 决胜对决（ABBA 各 2 段，共 4 段 × 标准档 2 组）
  ├─ 模型追加推算实测
  └─ 自动深化（差值未超噪声时继续加深，最多 N 轮；检测到疲劳立即停止）
        └─ 仍不可分辨 → 主观手感确认（二选一或按区间中点取值）
```

时长档位（配置页可选）：

| 档位 | 搜索轮数 | 决胜组数 | 预计 |
|---|---|---|---|
| 快速 | 3 | 1 | 约 8 分钟 |
| **标准（默认）** | 6 | 2 | 约 15 分钟 |
| 完整 | 8 | 3 | 约 18 分钟 |

### 为什么这样设计

- **ABBA 交替**：每组对决按 `A,B,B,A` 或 `B,A,A,B` 排列，位置均值恒为 2.5，**线性疲劳/学习漂移在配对差值里被数学抵消**。
- **脚本不重复**：每段用不同脚本（左右方向等量、距离分层抽样后打乱，并叠加会话级随机盐），避免「记住上一遍靶位」刷分；A/B 两套脚本难度构成一致，脚本难度差不会混进灵敏度比较。
- **锚点漂移补偿**：各阶段插入一小段**固定脚本**（尺子必须恒定），据此估算状态漂移并补偿分数，上限 ±15 分；休息后重建基线。
- **自适应难度**：得分 ≥86 难度 +2、≥78 +1、≤44 −1、≤34 −2（偏移 −2~+5），难度 Lv.1–12。太简单或太难都区分不出来，所以往中间拉。
- **定时休息**：按「有效瞄准时间」计时（默认每 5 分钟），到点强制建议休息并重新校准。
- **判定门槛**：搜索单轮差值需 > 4 分（`SEARCH_MARGIN`）才算分出胜负；决胜用配对样本差值均值与噪声阈值 `max(2.0, 2×SE)` 比较。

### 任务类型

| 任务 | 家族 | 说明 |
|---|---|---|
| 快速定位 | 点击 | 目标可出现在 ±135°，考验大幅度拉枪 |
| 目标切换 | 点击 | 两靶都在前方（±约 50°），打**高亮**那个 |
| 微调点击 | 点击 | 小范围精细修正 |
| 平滑跟枪 | 跟枪 | **按住左键持续开火**，未命中枪声较闷、命中变亮 |
| 变速跟枪 | 跟枪 | 靶圈约为基准 1.60 倍半径，速度更低 |
| 快速变向跟枪 | 跟枪 | 靶圈约为基准 2.20 倍半径，换向更慢 |

跟枪类约占一半；靶圈半径即真实命中判定半径。

## 测试记录：导出 / 导入 / 继续测量

**导出**（结果页或配置页的按钮）得到一份纯文本 JSON，包含：

- 每个测过的候选灵敏度、**每一段的原始得分**与逐段瞄准数据
- 全部对决记录（含 ABBA 各段）、状态锚点、模型推算记录
- 结论：推荐值 / 不可分辨区间 / 判定依据 / 配对样本数
- 当时的配置（DPI / FOV / 基准 / 显示比例 / 时间）

文件头字段：`app: "apex-sens-lab"`、`schema: 1`（导入时会校验来源标记、格式版本与候选值合法性）。

**导入后**：结论用完整历史数据**重新判定**（和刚测完一样），配置一并恢复；「再深化一轮」「模型继续推算」「导出」都能直接在历史数据上继续。

**继续测量（收窄范围）**：在指定区间内重新布点 → 2 轮搜索（4 段）+ 1 次决胜对决（4 段）→ 收窄推荐值。窗口外的历史数据原样保留并一起参与比较。每次继续测量前自动留撤回点，可一键回退。

> **分次测试是推荐用法**：跨天 / 跨场次继续，每次只在上次的区间里逼近，能把练习效应与疲劳摊薄，比一次测到底更可靠。

## FOV 数值含义（容易搞错，务必对齐）

| 你的数字来自 | 选哪个 |
|---|---|
| 游戏内 FOV 滑块（70–110） | **水平 · 4:3 基准**（默认） |
| 攻略/工具，标明"16:9 水平" | 水平 · 16:9 基准 |
| 标明"垂直" | 垂直（输入范围自动切为 42–105） |

Apex 的 FOV 按 **4:3 基准的水平视野**计算：滑块 110 在 16:9 屏幕上约为水平 **124.6°**、垂直 **93.9°**。选错基准只会影响画面缩放与视野范围（灵敏度结论不受影响，因为同一会话内所有对比都在同一设置下进行），但**请先对齐再开始**。

110 以上需要启动项 / autoexec 执行 `cl_fovScale`（社区近似：1.00=70 / 1.27=90 / 1.55=110 / 1.70=120），请先在游戏内确认已生效。

## 已知限制

- **测试期间请勿切换标签页**：切走会丢指针锁定并自动暂停（`dt` 被 clamp，计时不会爆掉，但会多一次暂停/恢复）。
- **重开本段（R）丢弃该段数据**，重开的段会计入新的脚本，不计分。
- **主观手感确认只在统计不可分辨时出现**，不是每次都问。
- 目前结果页只能通过「重新配置」回到选择页（会刷新页面，内存中的导入记录会丢；需要保留就先导出）。
- 导入的记录文件若来自他人分享，其中的文本字段按纯文本处理，但请只导入你自己导出的文件。
- 浏览器策略导致的指针锁定失败（扩展拦截、iframe 缺 `allow-pointer-lock`）在极少数环境下无解，测试画面会给出「不锁定继续 / 结束测试」的出口。

## 二次开发提示

- 全部逻辑在一个 `<script>` 块里，按编号分节（配置 / 状态、FOV、音效、渲染、判定、流程…），搜索 `/* ====== N.` 可定位。
- **两条必须守住的不变量**（都曾真的被改坏，测试里有断言守着）：
  1. **页面显示/隐藏只由 `showPage()` 负责**。`body` 是纵向 flex，两个 panel 同时可见就会上下叠在一起。
  2. **进入测试画面必须走 `enterStage()`** —— 渲染循环只在它里面启动一次（幂等的 `startLoop`），漏掉就是永久黑屏。
- **用户激活顺序**：`requestPointerLock` 必须在 `requestFullscreen` **之前**发出，且两者都在同一次点击的同步段内（全屏会消耗瞬时激活）。`enterStage()` 与 `resume()` 都遵循这个顺序。
